# Отладка промпта на dev-задачах (шаг 07)

Промпт отлаживается **только** на `data/tasks_dev.jsonl` (dev-A1, dev-B1, dev-C1, dev-D1, dev-F1) и на строках
пула типа E (`run_classifier --dev`), на **всех** включённых моделях сразу. Под одну модель промпт не подгоняется
(вопрос самоконтроля № 10). Итераций не больше трёх. Каждая итерация поднимает `PROMPT_VERSION` в `src/prompts.py`.

Команды:
```bash
.venv/bin/python -m src.run_bank --experiment dev              # base-промпт, 5 dev-задач × модели
.venv/bin/python -m src.run_extra cot followup_doubt --dev     # режимы H6/H9 на dev-задачах
.venv/bin/python -m src.run_classifier --dev                   # тип E: 6 строк пула × 0/5/20 примеров
.venv/bin/python -m src.prompt_debug --write                   # пересчитать таблицы ниже по журналу
.venv/bin/python -m src.prompt_debug freeze                    # заморозка: prompt_version + prompt_hash в config
```

## Наблюдения по формату (для решения о v2, когда ответят все модели)

- qwen3-8b, dev-D1: модель поставила код **после** «ОТВЕТ:» вместо «ОТВЕТ: код выше», и код в ответе повторён
  дважды (два блока ```python, копии отличаются). `parse.extract_code` берёт самый длинный блок и ставит
  пометку «блоков кода 2». Если так же поступят другие модели, в v2 можно уточнить `FORMAT["code"]`
  («строку ОТВЕТ пиши после блока кода, код не повторяй»). Если только qwen, промпт не менять: это была бы
  подгонка под одну модель.
- В остальных ответах qwen3-8b (base, cot, followup_doubt, тип E) строки ОТВЕТ и УВЕРЕННОСТЬ на месте,
  `<think>` в ответах нет. Подробности — в таблицах ниже.
- Тип E: qwen3-8b рассуждает перед ответом (выход сотни токенов, см. таблицу токенов), хотя формат этого
  не требует. Это влияет на бюджет шага 09, но не на разбор ответа.
