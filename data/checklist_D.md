# Чек-лист методологических ошибок для типа D

Источник: задание ЛР3, раздел «Метрики оценки → Код (тип D)». Проверяют **два человека независимо и вслепую** (листы готовит шаг 10). Модель-автор кода проверяющему не видна.

Код из ответа модели запускается **без правок** (`src/exec_code.py`, шаг 05). Отдельно от чек-листа фиксируются:
- **pass@1** — программа выполнилась без ошибок с первой попытки;
- **корректность результата** — напечатанная метрика отличается от `reference_metric` задачи не больше чем на `tolerance` (относительный допуск).

Для каждой программы по каждому пункту ставится **1** (ошибка есть), **0** (ошибки нет) или **н/п** (пункт неприменим, например стратификация в регрессии).

| # | Ошибка | Как выглядит в коде | Пример исправления |
|---|--------|---------------------|--------------------|
| 1 | **Масштабирование (или другой препроцессинг) до разбиения** | `StandardScaler().fit_transform(X)` / `PCA().fit(X)` до `train_test_split` или вне `Pipeline` при кросс-валидации: статистики теста утекают в обучение | `make_pipeline(StandardScaler(), SVC())`, `fit` только на обучающей части |
| 2 | **Подбор гиперпараметров по тесту** | цикл по `C`/`k`/`max_depth` с выбором лучшего по `score(X_test, y_test)`; `GridSearchCV(...).fit(X, y)` на всех данных, а затем оценка на части тех же данных | `GridSearchCV` только на `X_train`, тест используется один раз в конце |
| 3 | **Оценка на обучающей выборке** | итоговая метрика считается на `X_train` (или на всех данных, на которых обучали) | метрика на отложенном `X_test` или на кросс-валидации |
| 4 | **Accuracy при сильном дисбалансе** | при доле редкого класса ≲ 10% итоговая метрика или `scoring` для подбора — accuracy (в т. ч. неявно: `scoring` по умолчанию в `GridSearchCV`/`cross_val_score`) | F1 / recall редкого класса, balanced accuracy, ROC AUC, PR AUC; `scoring=` задан явно |
| 5 | **Нет стратификации** | классификация (особенно несбалансированная) без `stratify=y` в `train_test_split`; `KFold` без перемешивания на упорядоченных данных | `train_test_split(..., stratify=y)`, `StratifiedKFold(shuffle=True, random_state=...)` |
| 6 | **Не зафиксирован random_state** | случайность без seed: `train_test_split`, `KFold(shuffle=True)`, `RandomForest`, `KMeans`, `make_classification` без `random_state` (кроме случаев, когда его задаёт условие) | `random_state=42` везде, где есть случайность |

Правила оценки:
- Пункт отмечается, только если ошибка **видна в коде**. Сомнение трактуется в пользу кода, комментарий пишется в поле «примечание».
- Если программа упала до места, где ошибка проявилась бы, пункт всё равно оценивается по коду.
- **Нет масштабирования для метода на расстояниях** (kNN, SVM с RBF-ядром, KMeans) — обязательно записать в «примечание» (решение 15.10.2026; пункты 1–6 взяты из задания и не меняются). Корректность метрики такие решения обычно и так отсеивает (D4: без скейлера 0,71–0,78 при эталоне 0,9556).
- Ошибки, которых нет в списке (например, утечка целевой переменной через признак), записываются в «примечание»: в метрику доли методологических ошибок они не входят, но пригодятся для разбора ошибок.
- **Доля методологических ошибок** по модели = доля программ, где отмечен хотя бы один пункт 1–6 (дополнительно: среднее число пунктов на программу).

Связь с задачами банка: в `notes` у D1–D3 перечислены ловушки, на которые задача рассчитана (например, D3: подбор по accuracy при 5% редкого класса).
