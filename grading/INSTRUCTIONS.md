# Инструкция для проверяющих (слепая проверка B, C, D)

Вы оцениваете ответы языковых моделей на задачи по классическому ML. Названия моделей и компаний из ответов убраны и заменены на `[название скрыто]`. Проверяющих двое, каждый работает со своим файлом:

- проверяющий 1 — `grading/sheet_r1.csv`;
- проверяющий 2 — `grading/sheet_r2.csv`.

Строки в файлах одинаковые.

## Главные правила

1. **Работайте независимо.** Не обсуждайте оценки друг с другом, пока оба листа не заполнены. Не смотрите чужой лист. По расхождениям двух проверяющих считается каппа Коэна, поэтому обсуждение заранее испортит результат.
2. **Не открывайте `grading/key_DO_NOT_OPEN.csv`.** В нём указано, какая модель дала каждый ответ. Не ищите ответы в `logs/` и `results/` по тексту.
3. **Не пытайтесь угадать модель по стилю.** Оценивайте только содержание по рубрике.
4. **Не поручайте оценку LLM**, ни целиком, ни частично (вопрос самоконтроля № 3).
5. Сомневаетесь — ставьте оценку по рубрике и пишите сомнение в `comment`.

## Как открыть и сохранить лист

- Это CSV в кодировке UTF-8, разделитель — запятая. В Google Таблицах: «Файл → Импорт». В LibreOffice: открыть, указать UTF-8 и запятую. В Excel: «Данные → Из текста/CSV», UTF-8.
- Не меняйте порядок и названия столбцов, не удаляйте строки, не меняйте `item_id` и текст в `answer_text`.
- Сохраните результат под тем же именем в формате CSV. Подходит разделитель «,» или «;» и кодировка UTF-8 или Windows-1251: программа поймёт оба варианта. Перед сохранением сделайте копию.
- Ключ `key_DO_NOT_OPEN.csv` лежит в той же папке. Удобнее, если автор работы выдаст каждому проверяющему только его лист и эту инструкцию.

## Что заполнять

Заполните **все пустые клетки** в столбцах оценок. Клетки с «—» к строке не относятся, оставьте их как есть. Не ставьте «—» в пустую клетку: если пункт неприменим, пишите «н/п». В `comment` можно писать что угодно.

| Столбец | Строки | Значения |
|---|---|---|
| `score_0_2` | B, C | 0, 1 или 2 по рубрике в столбце `rubric` |
| `d1_…` – `d6_…` | D | **1** — ошибка есть, **0** — ошибки нет, **н/п** — пункт неприменим |
| `d_result_correct` | D, если клетка пустая | **1** — код печатает верную итоговую метрику (в пределах допуска из `reference`), **0** — нет |

В столбце `human_agrees` листа `parser_spotcheck.csv` пишется только «да» или «нет».

Остальные столбцы нужны для справки:
- `task_text` — условие, которое получила модель;
- `reference` — эталон;
- `rubric` — рубрика или чек-лист;
- `answer_text` — ответ модели;
- `exec_result` — результат запуска кода D без правок;
- `auto_metric` — автопроверка метрики D.

### Тип B — обоснование утверждения «верно / неверно»

Сам вердикт уже проверен автоматически. Вы оцениваете вердикт **вместе с обоснованием** по рубрике задачи:
- **2** — вердикт верный, обоснование содержит ключевые аргументы и не содержит грубых ошибок;
- **1** — вердикт верный, но обоснование неполное или с ошибкой;
- **0** — вердикт неверный, обоснования нет или оно неверное по существу.

Если в рубрике задачи (`score_2` / `score_1` / `score_0`) написано конкретнее, действует рубрика.

### Тип C — выбор метода

- **2** — приемлемый метод и **все** обязательные аргументы из рубрики;
- **1** — приемлемый метод, но пропущен обязательный аргумент; или спорный метод с верными аргументами;
- **0** — неприемлемый метод или нет обоснования.

Дополнительные аргументы (bonus) балл не повышают выше 2 и не обязательны. Метод, которого нет в списке приемлемых, оценивайте по существу и поясните оценку в `comment`.

### Тип D — код scikit-learn

Код был запущен **без правок**, результат лежит в `exec_result`. По каждому пункту чек-листа (`data/checklist_D.md`, там же примеры) поставьте 1, 0 или н/п:

| Столбец | Ошибка |
|---|---|
| `d1_preprocessing_before_split` | масштабирование или другой препроцессинг до разбиения (вне Pipeline) |
| `d2_tuning_on_test` | подбор гиперпараметров по тестовой выборке |
| `d3_eval_on_train` | итоговая оценка на обучающей выборке |
| `d4_accuracy_imbalance` | accuracy при сильном дисбалансе (в том числе scoring по умолчанию) |
| `d5_no_stratify` | нет стратификации в классификации |
| `d6_no_random_state` | не зафиксирован random_state там, где есть случайность |

- Пункт отмечается, только если ошибка **видна в коде**. Сомнение трактуется в пользу кода, само сомнение опишите в `comment`.
- Если код упал, пункты всё равно оцениваются по тексту кода.
- Если кода в ответе нет, ставьте **н/п** по всем пунктам (оценивать нечего), а в `comment` пишите «кода нет».
- Ошибки вне списка (например, утечка целевой переменной) запишите в `comment`.
- `d_result_correct` заполняйте, если клетка пустая. Сравните **итоговую** метрику из `exec_result` с `reference`. Если код упал, ничего не напечатал или кода нет, ставьте 0.
  - Автопроверка берёт число из последней строки вывода, где есть число. Поэтому она может ошибиться: например, взять `{'C': 10}` вместо accuracy. Её мнение в `auto_metric` — только подсказка.
  - Клетка «—» значит, что автопроверка нашла метрику в допуске («верно (авто)»). Если вы с этим не согласны, напишите об этом в `comment`.

## Когда закончили

Сообщите автору работы. Полноту обоих листов проверяет команда `.venv/bin/python -m src.checks g2`. Если каппа Коэна окажется ниже 0,6, рубрику уточнят, и оценку придётся повторить.
