# Цель
Каркас отчёта по структуре из PDF. Фактические разделы заполняются автоматически, выводы — места для человека. Плюс проверка воспроизводимости.

# Что сделать
1. `src/build_report.py` → `report/report.md`. Числа берутся из `results/summary_metrics.json`, `config/*.json`, `results/run_manifest.json` и `data/tasks.jsonl`; руками ничего не вписывается. Если реальных данных нет, отчёт собирается с пометками «нет данных», шаг `deferred`.
   Структура отчёта (из PDF):
   1. Введение: выбранные гипотезы и прогноз — из `hypotheses.md` со ссылкой на хэш коммита. Текст введения: `<!-- ЧЕЛОВЕК: ... -->`.
   2. Методика (заполняется автоматически):
      - модели, точные id, `model_reported`, даты, параметры;
      - полный текст промпта и его версия;
      - состав банка (таблица «тип × тема», доля своих задач);
      - способ проверки, каппа, железо для локальной модели.
   3. Результаты: таблицы с CI, обязательные рисунки, результаты тестов по гипотезам (числа). Вердикт по каждой гипотезе — `<!-- ЧЕЛОВЕК -->`.
   4. Разбор пяти ошибок: `<!-- ЧЕЛОВЕК -->`.
   5. Ограничения (не меньше трёх): `<!-- ЧЕЛОВЕК -->`.
   6. Рекомендации: пустая таблица «тип задачи → можно доверять / проверять выборочно / не доверять», заполняет человек.
2. `report/error_candidates.md` — 10–15 кандидатов на «интересные ошибки», отобранных по логам: неверный ответ при высокой уверенности, переворот после «ты ошибся», выдуманное число в задаче с недостающими данными, код с утечкой и т. п. Для каждого: задача, модель, эталон, **точная цитата ответа** из лога и call_id. Анализ причин не пишешь.
3. `report/selfcheck_questions.md` — 12 вопросов самоконтроля из PDF. Под каждым пустое место для ответа и ссылка на относящиеся к нему числа или ячейки ноутбука. Ответы не пишешь.
4. `report/slides_outline.md` — структура доклада на 5 минут: какие рисунки и таблицы куда, места под выводы человека.
5. Проверка воспроизводимости, если реальные данные есть:
   - создать чистое venv во временной папке из `requirements.txt`;
   - выполнить ноутбук;
   - убедиться, что `results/summary_metrics.json` совпадает с исходным;
   - результат записать в handoff и в `docs/reproducibility.md`.
6. Финальная ревизия HUMAN_TODO.md: актуальные пункты G3, удалены устаревшие.
7. Финальная ревизия README: полная инструкция «с нуля до отчёта».
