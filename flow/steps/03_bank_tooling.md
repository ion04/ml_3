# Цель
Инструменты банка задач, черновики задач и шаблоны гипотез. **Задачи «свои» придумывает человек** (по заданию не меньше половины банка), эталоны тоже подтверждает человек. Твоя роль — сделать так, чтобы человеку осталось только заполнить заготовки и проверить их.

# Что сделать
1. `src/bank.py` — схема задачи. Одна строка JSONL; поля из шаблона PDF плюс служебные:
   - `id`, `type` (A|B|C|D|E|F);
   - `topic` (linreg|logreg|knn|trees|ensembles|svm|bayes|clustering|pca|metrics);
   - `text_ru`, `text_en`, `reference`, `tolerance` (относительный, по умолчанию 0.01);
   - `source` (учебник|свои), `difficulty` (1–3);
   - `answer_kind` (number|numbers|bool|label|text|code|cannot_determine);
   - `pair_id`, `variant` (original|modified|missing_data|distractor|paraphrase|verbal|formula|null);
   - `rubric` (для C), `reference_code` и `reference_metric` (для D);
   - `reference_status` (agent_draft|verified|todo), `notes`.
   CLI:
   - `.venv/bin/python -m src.bank validate` — проверка схемы, предупреждения о незаполненном;
   - `... validate --final` — строгая проверка:
     - в банке 30–40 задач;
     - типов A, B, C, D, F не меньше 5 каждого;
     - в типе B примерно половина ложных утверждений;
     - все эталоны в статусе `verified`;
     - не меньше половины задач с `source == "свои"`;
     - заполнен `text_en`;
     - у пар есть обе половины;
     - id не пересекаются с dev-задачами;
   - `... stats` — таблица «тип × тема».
2. `data/tasks.jsonl` — черновик банка на 38 позиций. Распределение по типам: A 8, B 8, C 6, D 6, F 10 (из них 4–5 пар «учебник / изменённое условие», 3 с недостающими данными, 2 с лишними данными). Покрой все темы.
   - Позиции `source: "учебник"` (примерно половина банка) пиши сам: классические задачи учебного уровня с RU- и EN-текстом. Эталон считай кодом, скрипты положи в `data/refs/`. Статус `agent_draft`. Используй примеры из PDF.
   - Позиции `source: "свои"` — заготовки: `text_ru: "TODO(человек): ..."` с точным заданием (тип, тема, что придумать или изменить, например «изменённая версия F3: поменять числа так, чтобы ответ изменился»). Статус `todo`.
   - Заложи поля под гипотезы из `docs/hypotheses_guide.md` так, чтобы банк подошёл для любого рекомендованного набора. Это пары original/modified (H1), verbal/formula (H2), missing_data (H3). Перефразировки (H8) добавляются полем `paraphrase_ru/en` у части задач, их тоже заполняет человек или пишешь ты как черновик.
3. Тип D:
   - эталонные решения `data/d_reference/<id>.py` с фиксированным `random_state`;
   - запусти их и запиши `reference_metric` в задачу;
   - `data/checklist_D.md` — чек-лист методологических ошибок из PDF: масштабирование до разбиения; подбор гиперпараметров по тесту; оценка на обучающей выборке; accuracy при сильном дисбалансе; нет стратификации; не зафиксирован random_state.
4. Тип C: рубрика 0/1/2 для каждой задачи C в поле `rubric`. В неё входят приемлемые методы, обязательные аргументы и типичные ошибки.
5. `data/tasks_dev.jsonl` — 5 задач для отладки промпта (A, B, C, D, F), в оценку не входят. Их пишешь ты целиком, эталоны проверь кодом, статус `verified` (dev).
6. Гипотезы:
   - `docs/hypotheses_guide.md` — все 13 гипотез из PDF. Для каждой: какие задачи нужны в банке, какие дополнительные прогоны, сколько примерно вызовов API, какие метрика и тест. В конце два рекомендуемых набора: H1 + H6 + H9 (интересный) и H5 + H10 + H12 (дешёвый);
   - `hypotheses.md` — шаблон для 3 выбранных гипотез: формулировка, прогноз человека, обоснование, метрика, критерий решения, ссылка на коммит. **Прогноз не заполняй.**
7. `config/experiment.json`:
   - `"hypotheses": []` (заполняет человек);
   - `temperature_main: 0`, `sc_repeats: 5`, `sc_temperature: 0.7`;
   - `languages: ["ru"]` (если выбрана H4, добавится `"en"`);
   - `seed: 42`, `bootstrap_n: 1000`;
   - раздел `typeE` (заполнит шаг 06).
8. `src/checks.py` — проверки гейтов. Подкоманда `g1`, код 0 только если выполнены все условия:
   - `.env` содержит ключи для всех включённых моделей;
   - `src.smoke_test` проходит;
   - `src.bank validate --final` проходит;
   - в `config/experiment.json` 3 гипотезы из разных групп;
   - в `hypotheses.md` заполнены прогнозы, файл закоммичен и не изменён;
   - в `logs/calls.jsonl` нет записей experiment `main`/`extra` раньше коммита гипотез.
   Вывод — понятный список «что не так». Подкоманду `g2` добавит шаг 10. Пока это заглушка, которая возвращает код 1 с сообщением.
9. Тесты валидатора и проверок в `tests/`.
10. Добавь в HUMAN_TODO G1 конкретику: сколько заготовок «свои» и их id, какие черновики проверить.

Шаг `done`, если инструменты и черновики готовы. Заполнение заготовок — работа человека, она не делает шаг `deferred`.
