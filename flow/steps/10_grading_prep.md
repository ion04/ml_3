# Цель
Автопроверка, листы для слепой ручной проверки, тарифы (шаг 8 хода работы). Подготовка к гейту G2.

# Что сделать
1. Тарифы `config/pricing.json` нужны в любом случае, даже без прогонов:
   - официальные тарифы в рублях за токены для каждой модели; источник — официальные страницы, сверь через WebSearch/WebFetch;
   - если цена в USD, переведи по курсу ЦБ на дату проверки и запиши курс и источник;
   - поля: `source_url`, `date_checked`, `verified_by_human: false`;
   - для локальной модели цена 0, вместо неё — время и память.
2. Если оценочных прогонов ещё нет (шаг 08 отложен), сделай всё остальное на demo-данных (в `demo/`) и заверши шаг `deferred`.
3. Автопроверка A, B (вердикт), E и F → `results/graded_auto.jsonl`.
   Для D:
   - pass@1 из `results/d_exec.jsonl`;
   - корректность метрики относительно `reference_metric` в пределах допуска — автоматически, если метрику удалось извлечь, иначе в ручной лист.
4. Слепые листы, `src/blind.py`:
   - `grading/sheet_r1.csv` и `grading/sheet_r2.csv` — одинаковые строки, перемешанные с фиксированным seed.
   - Строки: обоснования B (рубрика 0–2), ответы C (рубрика 0–2), ответы D (чек-лист из `data/checklist_D.md` + корректность).
   - Столбцы: анонимный `item_id`, тип, текст задачи, рубрика или чек-лист, текст ответа, результат исполнения для D, пустые столбцы оценок, комментарий.
   - **Анонимизация**: убрать имя модели и самоназвания в тексте ответа («Я — GigaChat», «As DeepSeek», «Qwen», «YandexGPT», «Алиса» и т. п.).
   - Ключ `grading/key_DO_NOT_OPEN.csv` (item_id → model, task_id).
   - `grading/INSTRUCTIONS.md` для проверяющих: независимо, не обсуждать, не открывать ключ, как ставить 0/1/2.
5. `grading/parser_spotcheck.csv` — 20 случайных автопроверенных ответов (сырая строка ответа, распарсенное значение, эталон, вердикт), столбец `human_agrees` пустой.
6. `src/checks.py g2`: оба листа заполнены полностью, spotcheck заполнен, `pricing.verified_by_human == true`.
7. Добавить команду в `scripts/run_experiments.sh`.
