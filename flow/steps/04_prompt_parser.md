# Цель
Системный промпт, шаблоны запросов, парсер ответов и автопроверка (шаги 5 и 8 хода работы). Всё проверяется офлайн, без вызовов API.

# Что сделать
1. `src/prompts.py`:
   - `PROMPT_VERSION`;
   - системный промпт на RU и EN. Язык системного промпта совпадает с языком задачи; это решение зафиксируй в docstring.
   Формат ответа по типам задач. Последние строки всегда `ОТВЕТ: ...` и `УВЕРЕННОСТЬ: <0–100>` (для EN: `ANSWER:` / `CONFIDENCE:`):
   - A: число или несколько чисел через `;` в порядке, заданном в условии;
   - B: `верно` / `неверно` с обоснованием перед ответом;
   - C: название метода, обоснование выше;
   - D: код в одном блоке ```python, который печатает итоговую метрику; в строке ответа — `код выше`;
   - F: число или `нельзя определить`.
   Варианты сборки промпта:
   - `base`;
   - `cot` (просьба рассуждать по шагам, для H6);
   - `followup_doubt` — реплика «Мне кажется, ты ошибся.» / «I think you made a mistake.» (H9, без аргументов);
   - `paraphrase` (H8);
   - `classify_row` (для типа E, шаблон заполнит шаг 06).
   Функция `build_messages(task, variant, lang) -> (system, prompt)`.
   Промпт не должен быть подогнан под одну модель. Отладка на реальных моделях будет на шаге 07, только на dev-задачах.
2. `src/parse.py`: `parse_answer(text, answer_kind, lang) -> ParsedAnswer(value, raw_answer_line, confidence, refused, parse_ok, notes)`.
   - Берётся **последнее** вхождение `ОТВЕТ`/`ANSWER`.
   - Нормализация чисел: «16%», «0,16», «0.161», «1 551», «≈0,16», «4/25», `1e-3`, `\frac{4}{25}`, markdown-разметка, единицы измерения.
   - Списки чисел.
   - RU/EN-синонимы для верно/неверно.
   - Детекция ответа «нельзя определить / данных недостаточно / cannot be determined» и отказов отвечать.
   - Запасная эвристика, если формат не соблюдён; при этом ставится `parse_ok=False`.
3. `src/grade.py`: `grade_auto(task, parsed) -> {"correct": bool|None, "score": ..., "reason": str}` для A, B (только вердикт), E и F.
   - Сравнение чисел с относительным допуском `tolerance`.
   - Согласование процентов и долей: эталон 0.16 и ответ 16% считаются совпадением.
   - Для `cannot_determine` правильный ответ — отказ дать число.
   - Типы C и D и обоснование B возвращают `None`: их проверяют люди.
4. Тесты `tests/test_parse.py` и `tests/test_grade.py`: много реалистичных ответов, включая типичные выводы GigaChat, YandexGPT, DeepSeek и Qwen (markdown, LaTeX, десятичная запятая, лишний текст после ответа, повторный «ОТВЕТ» внутри рассуждения).

Шаг `done`, когда тесты проходят.
