# Цель
Скрипты прогонов (шаги 6–7 хода работы) и безопасный запуск кода типа D. На этом шаге всё проверяется **только на mock**; реальные прогоны будут на шаге 08.

# Что сделать
1. `src/run_bank.py`:
   `.venv/bin/python -m src.run_bank --experiment main --models all --lang ru [--types A,B] [--limit N] [--demo]`.
   - Перебирает задачи × модели и вызывает `ask` с meta `{task_id, type, variant, experiment, lang, prompt_version}`.
   - Разбирает ответ, ставит автооценку и пишет производную таблицу в `results/<experiment>_<lang>.jsonl`. С флагом `--demo` модели заменяются на mock, а всё пишется в `demo/`.
   - Скрипт идемпотентный (кэш), есть прогресс-бар.
   - Параллельность ограничена на уровне провайдера (2–4 потока), чтобы не упираться в rate limit.
   - Модель, которая выключена или для которой нет ключа, пропускается с понятным сообщением.
2. `src/run_extra.py` — дополнительные прогоны под гипотезы. Читает `config/experiment.json` и запускает только выбранные гипотезы, но реализовать нужно режимы для **всех**, кому нужны отдельные прогоны:
   - `cot` (H6): задачи A и B с CoT-промптом;
   - `selfconsistency` (H7): 5 повторов при T=0.7, ответ большинства;
   - `followup_doubt` (H9): только для задач, решённых верно в main, второй ход с `history`;
   - `paraphrase` (H8);
   - `lang_en` (H4): прогон на английском;
   - `verbal_formula` (H2).
   H1, H3, H5, H10, H11 и H13 считаются из main и типа E, отдельных прогонов не требуют; это нужно явно указать в выводе скрипта.
   Режим `--demo` работает так же, как в run_bank.
3. `src/exec_code.py` — запуск кода из ответов типа D.
   - Код извлекается из блока python и сохраняется **без правок** в `results/d_code/<model>/<task>.py`.
   - Запуск: `.venv/bin/python` во временной папке, таймаут 300 с, окружение без переменных с ключами (белый список: PATH, HOME, LANG и т. п.).
   - Сохраняется stdout, stderr, код возврата, время и извлечённая из stdout метрика. Результаты пишутся в `results/d_exec.jsonl`.
   - pass@1 = выполнился без ошибок с первой попытки.
4. `scripts/run_experiments.sh` — запуск всего эксперимента одной командой. Порядок: smoke-тест → `src.checks g1` → run_bank (main) → run_extra → exec_code → прогон типа E (шаг 06 добавит команду) → подготовка проверки (шаг 10 добавит). Скрипт останавливается на первой ошибке.
5. Тесты: end-to-end на mock-провайдере через `--demo` с небольшим фиктивным банком в `tests/fixtures/`. Проверить идемпотентность (второй запуск не делает новых вызовов) и что demo ничего не пишет в `logs/` и `results/`.
6. Дополнить README («Как запустить эксперимент»).

Шаг `done`, когда всё работает на mock.
